# Implementation Plan — Quran Daily Wird Telegram Bot

**الحالة:** مسوّدة للمراجعة (v1) — تاريخ الإنشاء: 2026-09-06
**هوية البوت:** الاسم **وِرْدُنا** · المعرّف [@WirdunaBot](https://t.me/WirdunaBot) · وضع الخصوصية مُفعّل (لا يقرأ رسائل المجموعة، والأوامر والأزرار تكفيه).

## 1. ملخّص المنتج (Product Summary)

بوت عربي يعمل داخل مجموعات تيليجرام، يرسل **وردًا يوميًا** من صفحات المصحف (صور)، ويتابع من أتمّ القراءة ومن لم يُتمّ، ثم يبدأ **بمناداة المتأخّرين** برسائل تحفيزية بعد فترة يحدّدها المشرف. البوت يحفظ **تقدّم المجموعة** حتى ختم المصحف كاملًا (604 صفحات)، ثم يبدأ ختمة جديدة.

**المبادئ الحاكمة:**
1. كل النصوص الظاهرة للمستخدم **بالعربية الفصحى** (طبقة نصوص واحدة `messages/ar.py` قابلة للترجمة لاحقًا).
2. **الاشتراك اختياري** — لا يُذكر (mention) إلا المشتركون.
3. الأسلوب **تحفيزي مُذكِّر بالآخرة**، لا تأنيبي ولا جارح.
4. **قابلية التوسّع**: بنية «مزوّدي محتوى» (Content Providers) تسمح بإضافة **التفسير، الأذكار، الأحاديث** لاحقًا دون إعادة كتابة.

## 2. ما تم التحقّق منه فعليًا (Verified Facts)

تم فحص `hafs.zip` (91 MB) الموجود في المجلد:

| العنصر | النتيجة |
|---|---|
| عدد الملفات | 1209 |
| صور الصفحات | `001.svg` … `604.svg` (604 ملف، مسار vector — نص مُحوّل إلى `<path>`) |
| بيانات مواضع الآيات | `001.json` … `604.json` — لكل آية: `ayahNumber, surahNumber, x, y, polygon, page_number, juz, ruku, hizb, manzil` |
| فهرس المصحف | `mushaf-content.json` (2.7 MB) — كل السور والآيات بنصّها + `page_number, juz, hizb, ruku, manzil` + رموز `marker` و `coded_name` |
| مقاسات SVG | الصفحتان 1 و 2 بمقاس `0 0 235 235` (مربّع)، والصفحات 3–604 بمقاس `0 0 345 550` ← **تحتاج توحيد** |
| التحويل إلى صور | `rsvg-convert -w 1240 -b white` يعمل بجودة ممتازة (~0.05 ث/صفحة) — تم اختباره على صفحتين (الفاتحة وصفحة كثيفة) والنتيجة واضحة تمامًا |
| الحجوم | PNG كامل ‎737 KB/صفحة (≈435 MB إجمالًا) · **PNG8 بـ32 لونًا ‎178 KB/صفحة (≈105 MB إجمالًا)** · JPEG q88 ‎459 KB |
| الأدوات المتاحة على الجهاز | `rsvg-convert` ✅ · `magick`/`convert` ✅ · `inkscape` ❌ |

**قرار الصور:** توليد `PNG8` (32 لونًا رماديًا) بعرض 1240px، مع توحيد الصفحتين 1–2 على لوحة بنسبة 345×550 (تمركز أفقي/عمودي على خلفية بيضاء) لتبدو الألبومات متناسقة. الصور تُولَّد مرة واحدة عبر سكربت بناء، وتُرفع لتيليجرام مرة واحدة ثم **يُخزَّن `file_id`** فتصبح الإرسالات التالية فورية وبلا رفع.

## 4. مخطّط قاعدة البيانات (SQLAlchemy ORM)

الجداول مُعرَّفة كنماذج SQLAlchemy 2.0 في `db/models.py`، والهجرات يولّدها Alembic
تلقائيًا منها (`alembic revision --autogenerate`). ما يلي هو الشكل المنطقي للمخطّط.

**اصطلاحات:** الطوابع الزمنية (`DateTime`) بتوقيت UTC · التواريخ (`Date`) والأوقات
(`Time`) محليّة بتوقيت المجموعة · القوائم تُخزَّن `JSON` لا نصوصًا مفصولة بفواصل ·
القيم المحدودة `StrEnum` (`AdvanceRule`, `TaskStatus`, `CompletionSource`, `BadgeKind`).
الهجرات تعمل بـ `render_as_batch=True` لأن SQLite لا يدعم `ALTER TABLE` الكامل.

```sql
-- المجموعات وإعداداتها
CREATE TABLE groups (
  chat_id            INTEGER PRIMARY KEY,
  title              TEXT,
  timezone           TEXT    NOT NULL DEFAULT 'Asia/Damascus',
  pages_per_day      INTEGER NOT NULL DEFAULT 2,   -- ختمة كل ~10 أشهر
  active_weekdays    TEXT    NOT NULL DEFAULT '0,1,2,3,4,5,6',  -- 0=الاثنين
  send_time          TEXT    NOT NULL DEFAULT '05:00',          -- محلي
  first_reminder_after_hours INTEGER NOT NULL DEFAULT 8,
  reminder_interval_hours    INTEGER NOT NULL DEFAULT 3,
  reminder_max_count         INTEGER NOT NULL DEFAULT 3,
  quiet_hours_start  TEXT    DEFAULT '23:00',   -- لا تذكير بعده
  quiet_hours_end    TEXT    DEFAULT '07:00',
  mentions_per_message INTEGER NOT NULL DEFAULT 4,
  day_close_time     TEXT    NOT NULL DEFAULT '23:59',
  weekly_report_enabled  INTEGER NOT NULL DEFAULT 1,
  weekly_report_weekday  INTEGER NOT NULL DEFAULT 4,      -- 4=الجمعة (0=الاثنين)
  weekly_report_time     TEXT    NOT NULL DEFAULT '20:00',
  week_start_weekday     INTEGER NOT NULL DEFAULT 5,      -- بداية الأسبوع: 5=السبت
  advance_rule       TEXT    NOT NULL DEFAULT 'anyone',  -- anyone|majority|all|always
  current_page       INTEGER NOT NULL DEFAULT 1,         -- أول صفحة للورد القادم
  khatmah_number     INTEGER NOT NULL DEFAULT 1,
  khatmah_started_on TEXT,
  is_active          INTEGER NOT NULL DEFAULT 1,
  created_at         TEXT NOT NULL
);

-- المشتركون (اختياري بالكامل)
CREATE TABLE subscribers (
  chat_id     INTEGER NOT NULL REFERENCES groups(chat_id) ON DELETE CASCADE,
  user_id     INTEGER NOT NULL,
  display_name TEXT   NOT NULL,   -- يُحدَّث عند كل تفاعل
  username    TEXT,
  joined_at   TEXT NOT NULL,
  left_at     TEXT,
  is_active   INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (chat_id, user_id)
);

-- ورد كل يوم
CREATE TABLE daily_tasks (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  chat_id      INTEGER NOT NULL REFERENCES groups(chat_id) ON DELETE CASCADE,
  task_date    TEXT    NOT NULL,          -- YYYY-MM-DD محلي
  page_start   INTEGER NOT NULL,
  page_end     INTEGER NOT NULL,
  message_id   INTEGER,                   -- رسالة الورد ذات الزر
  album_message_ids TEXT,                 -- JSON list
  poll_id      TEXT,
  status       TEXT NOT NULL DEFAULT 'open',  -- open|closed
  is_repeat_of INTEGER REFERENCES daily_tasks(id),
  sent_at      TEXT NOT NULL,
  closed_at    TEXT,
  UNIQUE (chat_id, task_date)
);

-- من أتمّ القراءة
CREATE TABLE completions (
  task_id  INTEGER NOT NULL REFERENCES daily_tasks(id) ON DELETE CASCADE,
  user_id  INTEGER NOT NULL,
  done_at  TEXT NOT NULL,
  source   TEXT NOT NULL,                 -- button|poll|command
  was_subscriber INTEGER NOT NULL,
  PRIMARY KEY (task_id, user_id)
);

-- إحصاءات تراكمية لكل عضو في كل مجموعة
CREATE TABLE user_stats (
  chat_id            INTEGER NOT NULL,
  user_id            INTEGER NOT NULL,
  total_done         INTEGER NOT NULL DEFAULT 0,
  total_missed       INTEGER NOT NULL DEFAULT 0,
  current_streak     INTEGER NOT NULL DEFAULT 0,
  best_streak        INTEGER NOT NULL DEFAULT 0,
  consecutive_missed INTEGER NOT NULL DEFAULT 0,
  last_done_date     TEXT,
  PRIMARY KEY (chat_id, user_id)
);

-- سجل التذكيرات (لمنع التكرار بعد إعادة التشغيل)
CREATE TABLE reminder_log (
  task_id    INTEGER NOT NULL REFERENCES daily_tasks(id) ON DELETE CASCADE,
  seq        INTEGER NOT NULL,
  sent_at    TEXT NOT NULL,
  message_ids TEXT,
  PRIMARY KEY (task_id, seq)
);

-- دعوة غير المشتركين (مرة كل أسبوع كحدّ أقصى)
CREATE TABLE nudges (
  chat_id       INTEGER NOT NULL,
  user_id       INTEGER NOT NULL,
  last_nudged_at TEXT NOT NULL,
  PRIMARY KEY (chat_id, user_id)
);

-- سجل التقارير الأسبوعية (يمنع التكرار بعد إعادة التشغيل)
CREATE TABLE weekly_reports (
  chat_id      INTEGER NOT NULL REFERENCES groups(chat_id) ON DELETE CASCADE,
  week_start   TEXT    NOT NULL,          -- YYYY-MM-DD أول يوم في الأسبوع
  week_end     TEXT    NOT NULL,
  sent_at      TEXT    NOT NULL,
  message_id   INTEGER,
  pages_read   INTEGER NOT NULL DEFAULT 0,
  active_days  INTEGER NOT NULL DEFAULT 0,
  perfect_user_ids TEXT,                  -- JSON list — لوحة الشرف
  PRIMARY KEY (chat_id, week_start)
);

-- الأوسمة المكتسبة (أسبوع كامل، ٣٠ يومًا، ختمة…)
CREATE TABLE badges (
  chat_id   INTEGER NOT NULL,
  user_id   INTEGER NOT NULL,
  badge     TEXT    NOT NULL,             -- perfect_week|streak_30|khatmah|…
  earned_at TEXT    NOT NULL,
  ref       TEXT,                         -- week_start أو رقم الختمة
  PRIMARY KEY (chat_id, user_id, badge, ref)
);

-- كاش file_id لصور الصفحات (لكل بوت)
CREATE TABLE page_media (
  page_no        INTEGER PRIMARY KEY,
  file_id        TEXT NOT NULL,
  file_unique_id TEXT,
  uploaded_at    TEXT NOT NULL
);

-- فهرس المصحف (من mushaf-content.json) — للعناوين والتفسير مستقبلًا
CREATE TABLE surahs (number INTEGER PRIMARY KEY, name TEXT NOT NULL, ayah_count INTEGER);
CREATE TABLE page_index (
  page_no    INTEGER PRIMARY KEY,
  juz        INTEGER, hizb INTEGER,
  first_surah INTEGER, first_ayah INTEGER,
  last_surah  INTEGER, last_ayah  INTEGER,
  surah_names TEXT                    -- "البقرة، آل عمران"
);
CREATE TABLE ayahs (           -- للتفسير/البحث مستقبلًا
  surah INTEGER, number INTEGER, page_no INTEGER, text TEXT,
  juz INTEGER, hizb INTEGER, PRIMARY KEY (surah, number)
);
```

WAL mode + `PRAGMA foreign_keys=ON` + `aiosqlite`. الهجرات ملفات SQL مرقّمة يطبّقها المشغّل عند الإقلاع.

## 5. تدفّق العمل اليومي (Daily Flow)

```
05:00 (توقيت المجموعة، في يوم مُفعّل)
  └─ send_daily
       ├─ تحديد النطاق: [current_page … current_page + pages_per_day - 1]
       ├─ إرسال ألبوم الصور (10 كحدّ أقصى للرسالة الواحدة → تقسيم تلقائي)
       ├─ إرسال «رسالة الورد» تحتها زر:  ✅ قرأتُ وردي   |   📊 من أنجز؟
       │    النص: التاريخ · الصفحات · الجزء/السور · عبارة تحفيزية · عدّاد الإنجاز
       └─ تسجيل daily_task + جدولة التذكيرات

عند ضغط الزر (CallbackQuery)
  ├─ مشترك؟  → تسجيل الإنجاز · تحديث الإحصاءات · تعديل الرسالة لتُظهر قائمة المنجزين
  └─ غير مشترك؟ → تسجيل الإنجاز أيضًا + تهنئة عبر answerCallbackQuery
                  + (مرّة كل أسبوع) رسالة عامة تدعوه للاشتراك

13:00 — بعد 8 ساعات (first_reminder_after_hours)
  └─ remind (seq=1)
       ├─ من لم يُنجز من المشتركين → تقسيم إلى دفعات (4 منشن/رسالة)
       ├─ كل رسالة: منشن + عبارة تحفيزية + «أنجز فلان وفلان… وبقي كذا»
       └─ من فاتته أيام سابقة: تُضاف عبارة «فاتك X من الأيام…» (تقصير)

16:00 و 19:00 — كل 3 ساعات حتى reminder_max_count → remind (seq=2,3) بلهجة أقوى تدريجيًا
  (تُتخطّى أي تذكيرة تقع داخل «ساعات الهدوء»)

23:59 close_day
  ├─ إغلاق الورد · تحديث total_missed / consecutive_missed / streaks
  ├─ تقرير يومي مختصر: من أنجز · نسبة الإنجاز · المتصدّرون
  └─ قرار التقدّم حسب advance_rule:
        anyone  → إن أنجز شخص واحد على الأقل: current_page += pages_per_day
        all     → لا يتقدّم إلا بإنجاز الجميع
        majority→ يتقدّم بإنجاز أكثر من النصف
        always  → يتقدّم دائمًا
      وإلا: الورد نفسه يُعاد غدًا (is_repeat_of)
  └─ إن تجاوز current_page 604 → 🎉 إعلان ختم المصحف · khatmah_number += 1 · العودة للصفحة 1

الجمعة 20:00 (weekly_report_weekday/time)  ← يُنفَّذ بعد close_day لليوم السابق
  └─ weekly_report
       ├─ حساب أيام الأسبوع المُفعّلة فقط (لا تُحتسب أيام العطلة ولا الأيام المُعادة)
       ├─ 🏅 لوحة الشرف: من أنجز كل يوم مُفعّل في الأسبوع بلا تخلّف
       ├─ 📖 تقدّم الختمة: صفحة X من 604 · النسبة · شريط تقدّم · صفحات الأسبوع
       ├─ 🔥 أطول السلاسل المتتالية · نسبة إنجاز المجموعة هذا الأسبوع
       ├─ ⏳ تقدير الوقت المتبقي للختمة بحسب معدّل الأسابيع الماضية
       ├─ منح وسام perfect_week لكل من في لوحة الشرف (جدول badges)
       └─ تسجيل التقرير في weekly_reports (idempotent — لا يُرسل مرتين)
```

**نقاط دقّة مهمة:**
- **الأيام غير المُفعّلة:** لا يُرسل ورد ولا تذكير، والصفحات لا تتقدّم.
- **إعادة التشغيل:** عند الإقلاع يُعاد بناء كل الـ jobs من قاعدة البيانات (`scheduler.rebuild_all()`)، وتُقارَن `reminder_log` لتفادي إرسال تذكيرة مكرّرة أو مفقودة.
- **حدود تيليجرام:** استخدام `AIORateLimiter` (‎`python-telegram-bot[rate-limiter]`‎) — الحدّ العملي ~20 رسالة/دقيقة للمجموعة الواحدة. رسائل التذكير المقسّمة تُرسل بفواصل زمنية صغيرة.
- **أسماء لوحة الشرف بلا منشن:** تُعرض الأسماء نصًّا فقط (`html.escape`) دون رابط `tg://user` — احتفاء بلا إزعاج. المنشن مقصور على تذكيرات المتأخّرين.
- **لوحة الشرف:** «بلا تخلّف» تعني إنجاز كل يوم **مُفعّل** مرّ عليه العضو وهو مشترك. من اشترك في منتصف الأسبوع يُحاسَب على الأيام التي تلت اشتراكه فقط (لا يُظلم ولا يُمنح الوسام بلا استحقاق).
- **الورد المُعاد يُحاسَب عليه كيومٍ كامل** في لوحة الشرف، لأن `close_day` يسجّل تقصيرًا على
  كل يوم بما فيه المُعاد؛ ولو استُثني هنا لاختلفت اللوحة عن السلسلة في حقّ العضو نفسه.
  أمّا **الصفحات** فلا تُحتسب مرّتين: إعادة قراءة الصفحة ٥ لا تُقدّم الختمة، فلا تدخل في
  «قرأنا هذا الأسبوع».
- **تقدير موعد الختمة** يُبنى على معدّل الأسابيع الماضية الفعلي (من جدول `weekly_reports`)
  لا على الإعدادات، فالمجموعة تُحاسَب بما قرأته لا بما نوت أن تقرأه.
- **بداية الأسبوع:** قابلة للضبط (`week_start_weekday`)، والافتراضي **السبت → الجمعة** بما يوافق العرف في المنطقة، والتقرير يُرسل الجمعة مساءً.
- **إغلاق اليوم يعمل كل يوم** (بلا `days=`)، حتى يُغلق ليلتَه وردٌ أُرسل في آخر يوم مُفعّل ولو كان الغد يومًا معطّلًا.
- **التقدّم يُحسب بالمشتركين وحدهم:** ضغطة الضيف تُسجَّل ويُشكر عليها، لكنها لا تُحرّك الصفحات ولا تدخل في نسبة الإنجاز، ولا يُحسب على الضيف تقصير.
- **وسم الإعادة:** بعد أن صار `close_day` يُغلق ورد كل ليلة، لم يعد بقاء الورد مفتوحًا دليلَ الإعادة؛ فصار `send_wird` يتعرّف عليها بمطابقة صفحات اليوم لصفحات آخر ورد سابق ويضبط `is_repeat_of` عليه — ويبقى إغلاقُ ورد مفتوح قديم شبكةَ أمان إن تعطّل `close_day` (انقطاع أو إعادة تشغيل). وإن كان بعضهم قد أتمّه (في قواعد `all` و `majority`) تُستعمل صيغة «لم يُتمّه الجميع بعد» بدل «لم يُتمّه أحد».
- **المنشن:** `<a href="tg://user?id=123">الاسم</a>` بصيغة HTML — يعمل حتى لمن لا يملك `@username`، لأن المشترك تفاعل مع البوت مسبقًا. الأسماء تُمرَّر عبر `html.escape`.

## 5ب. متغيّرات البيئة ووضع التشغيل

يعمل البوت في وضعين، ويُختار الوضع تلقائيًا: **إن كان `WEBHOOK_URL` مضبوطًا يعمل بالـ webhook، وإلا يعمل بالـ long polling.**

| المتغيّر | مطلوب؟ | الافتراضي | الوصف |
|---|---|---|---|
| `BOT_TOKEN` | ✅ | — | توكن البوت من BotFather |
| `DB_PATH` | — | `data/bot.db` | مسار قاعدة SQLite |
| `PAGES_DIR` | — | `assets/pages` | مجلد صور الصفحات المولّدة |
| `DEFAULT_TIMEZONE` | — | `Asia/Damascus` | المنطقة الزمنية لأي مجموعة جديدة |
| `LOG_LEVEL` | — | `INFO` | مستوى السجلّات |
| **`WEBHOOK_URL`** | — | *(فارغ)* | **مفتاح التبديل**: عند ضبطه يعمل البوت بالـ webhook. العنوان العام الكامل، مثال: `https://bot.example.com` |
| `SECRET_TOKEN` | webhook فقط | — | يُمرَّر كـ `secret_token` ويتحقّق منه تيليجرام عبر ترويسة `X-Telegram-Bot-Api-Secret-Token` |
| `PORT` | webhook فقط | `8443` | منفذ الاستماع المحلي |
| `URL_PATH` | webhook فقط | *(التوكن)* | مسار الـ endpoint |

**منطق الإقلاع:**

```python
if settings.webhook_url:
    await application.run_webhook(
        listen="0.0.0.0",
        port=settings.port,
        url_path=settings.url_path,
        secret_token=settings.secret_token,
        webhook_url=f"{settings.webhook_url.rstrip('/')}/{settings.url_path}",
        allowed_updates=Update.ALL_TYPES,
        drop_pending_updates=False,
    )
else:
    await application.run_polling(allowed_updates=Update.ALL_TYPES)
```

ملاحظات: `allowed_updates` يجب أن يشمل `callback_query` و `my_chat_member` و `chat_member` وإلا لن تصل التحديثات. يُستخدم `drop_pending_updates=False` كي لا تضيع ضغطات الأزرار أثناء إعادة التشغيل. في وضع الـ webhook يُوضع nginx أمام البوت لإنهاء TLS.

### أوامر/لوحة المشرفين (`/settings` → قائمة أزرار تفاعلية)
- عدد الصفحات اليومية · أيام الأسبوع · وقت الإرسال · المنطقة الزمنية
- موعد أول تذكير · الفاصل بين التذكيرات · عددها · ساعات الهدوء
- عدد المنشن لكل رسالة · قاعدة التقدّم (`advance_rule`)
- التقرير الأسبوعي: تفعيله · يوم إرساله · وقته · اليوم الذي يبدأ به الأسبوع
- تعيين الصفحة الحالية يدويًا (`/setpage 350`) · بدء ختمة جديدة
- إيقاف/تشغيل البوت مؤقتًا · إرسال الورد الآن (`/sendnow`)
- إدارة المشتركين (عرض/إزالة)

**اللوحة بالأزرار وحدها** — لا كتابة ولا `ConversationHandler`، فلا حالة محادثة تضيع عند
إعادة التشغيل، ورسالة واحدة تُعدَّل في مكانها بين الشاشات. الأوقات تُضبط بخطوات نصف ساعة
(تلتفّ حول منتصف الليل)، والمنطقة الزمنية تُختار من قائمة مدن.

**الانضمام إلى ختمة بدأت قبل البوت:** كثير من المجموعات تكون في ختمة يدوية قبل إضافة
البوت، فلا بدّ أن تُكمل من صفحتها لا أن تبدأ من الأولى. الأمر `/setpage 350` هو الطريق —
والأزرار لا تصلح للقفزات الكبيرة — ولذلك يُذكر الأمر في رسالة الترحيب بالمجموعة وفي شاشة
«الصفحة الحالية»، ويردّ البوت بالجزء واسم السورة ليتأكّد المشرف أنه وقف على الموضع الصحيح.

كل الإعدادات محميّة بفحص `getChatMember` للتأكد من أن المُرسِل مشرف — على كل ضغطة زر لا
عند فتح اللوحة فقط، لأن اللوحة تبقى في المجموعة وأزرارها في متناول الجميع. والمشرف
المجهول (anonymous admin) يُعرف بهويّة `@GroupAnonymousBot` لأن `getChatMember` لا تصلح له.

```
وَصَلَّى اللهُ عَلَى نَبِيِّنَا مُحَمَّدٍ وَعَلَى آلِهِ وَصَحْبِهِ وَسَلَّمَ.
```

*تخريج المقاطع:* «اللهم اجعل القرآن ربيع قلوبنا…» من حديث ابن مسعود — رواه أحمد وابن حبان (حسن). «اللهم أصلح لي ديني…» — رواه مسلم. وباقي الدعاء من المأثور عن السلف في ختم القرآن.

**ملاحظة تنفيذية:** يُخزَّن الدعاء في `messages/ar.py` كنصّ ثابت (لا ضمن مجمّعات العشوائية)، ويُرسل بـ `parse_mode=None` حفاظًا على التشكيل والأسطر.

**نقاط مفتوحة على العبارات:**
- هل تريد إضافة **أدعية ختم المصحف** كاملة عند إنهاء الختمة؟
- هل تفضّل نبرة أشدّ في التذكير الأخير أم الإبقاء على اللين؟
- هل نضيف **بشارة أسبوعية** (تقرير كل جمعة) بأفضل المداومين؟

### ما استقرّ عليه أمر المتانة (المرحلة 10)

- **الطرد من المجموعة (`Forbidden`) هو الخطأ الوحيد الذي لا تُصلحه إعادة المحاولة**، فيُعطَّل
  عنده تفعيل المجموعة بدل أن يُعاد الإرسال إليها كل صباح إلى الأبد. والتعطيل لا يحذف شيئًا:
  الصفحة والسلاسل والاشتراكات كلها تبقى، فإن أُعيد البوت استأنف من موضعه. وقد اقتضى هذا أن
  تُمرَّر `Forbidden` من داخل المهام التي تبتلع أخطاء الإرسال (`close_day` و `remind` و
  التقرير الأسبوعي) حتى تصل إلى المهمّة نفسها، وإلا ظلّت المجموعة المطرودة تُغلق أيامها ليلًا بلا نهاية.
- **النسخ الاحتياطي بواجهة SQLite للنسخ الحيّ لا بـ `cp`**: البوت لا يتوقّف لأجل نسخته، و`cp`
  على قاعدة قيد الكتابة قد يلتقط كتابة نصف مكتملة. والنسخ يعمل داخل البوت لا في `cron` ليكون
  النشر وحدة واحدة: `systemctl start` يعطيك النسخ الاحتياطي أيضًا.
- **الخدمة تشغّل `python` الخاص بالبيئة الافتراضية مباشرة** لا `uv run`، لأن `uv` يحتاج ذاكرة
  مؤقّتة قابلة للكتابة بينما `ProtectSystem=strict` يمنع ذلك — والبوت لا يحتاج من `uv` شيئًا وقت التشغيل.

## 10. أفكار تحسين مقترحة (للنقاش)

1. **التزكية بالتلاوة الصوتية** — زر «استمع» يرسل رابط تلاوة الصفحة (Everyayah / QuranicAudio).
2. **وضع رمضان** — جزء يوميًا تلقائيًا لختمة في 30 يومًا.
3. **الورد الفردي بالخاص** — من يتخلّف يصله تذكير خاص بدل الإحراج في المجموعة (اختياري لكل عضو).
4. **توسيع نظام الأوسمة** — شارات إضافية فوق `perfect_week` (٣٠ يومًا متتالية، ختمة كاملة، أول من ينجز في اليوم) وعرضها بجوار الاسم في `/me` و `/top`.
5. **`/tafsir <صفحة>`** — يستفيد من `ayahs` المخزّنة (تمهيد للمرحلة 11).
6. **تصدير تقرير الختمة** — PDF/صورة ملخّصة عند إتمام الختمة.
7. **دعم عدّة مجموعات لنفس العضو** — الإحصاءات منفصلة لكل مجموعة (مطبَّق أصلًا في المخطّط).
8. **نسخة احتياطية/استيراد الإعدادات** بأمر مشرف.

## 11. قرارات مُعتمدة (Locked Decisions) ✅

| القرار | الاختيار |
|---|---|
| آلية تسجيل الإنجاز | **زر Inline** تحت رسالة الورد (`✅ قرأتُ وردي` + `📊 من أنجز؟`)، والرسالة تُعدَّل حيًّا لعرض أسماء المنجزين والعدّاد. استفتاء تيليجرام **مستبعد** (لا يمكن تعديله لعرض القائمة). يبقى عمود `poll_id` في المخطّط فارغًا كاحتياط مستقبلي فقط. |
| قاعدة تقدّم الصفحات | **`anyone`** — تتقدّم الصفحات إذا أنجز مشترك واحد على الأقل؛ وتُعاد صفحات اليوم نفسها غدًا فقط إذا لم يُنجزها أحد. (تبقى `all` / `majority` / `always` متاحة كخيارات للمشرف، والافتراضي `anyone`.) |

| التقرير الأسبوعي | **مُعتمد كميزة أساسية** — لوحة شرف كل جمعة 20:00 بتوقيت المجموعة: أسماء من أتمّوا الأسبوع بلا تخلّف + تقدّم الختمة (صفحة/604 ونسبة وشريط) + أطول السلاسل + معدّل الإنجاز + تقدير موعد الختمة. الأسبوع افتراضيًا السبت→الجمعة، وكلّه قابل للضبط. |
